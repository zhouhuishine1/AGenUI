# AGenUI「AI 提示词 → 卡片生成」方案整理

> 基于仓库代码与文档梳理，覆盖三个问题：① AI 生成卡片整体过程；② 如何保障精准使用内置组件；③ 新增组件要做什么。

---

## 一、AI 提示词生成卡片的整体过程

整条链路复用 `skills/a2ui-generation/` 这份 A2UI 生成 Skill，Studio（`playground/studio/`）把它接入为服务端流水线：

```
用户 Query (+ 可选 DTO / 设计图)
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 1. Prompt 构建 (prompt_builder.py)                   │
│    system prompt = SKILL.md + 参考文档 + 校验契约 +   │
│                    输出格式指令                      │
│    user prompt   = Query + 数据文件 + 绑定提示       │
└─────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 2. LLM 流式生成 (providers.py)                       │
│    输出两个 JSON 块：                                │
│    ① updateComponents  (组件树/布局/样式/绑定路径)   │
│    ② updateDataModel   (绑定路径对应的数据)          │
└─────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 3. 提取与校验 (extractor.py + validate_a2ui.py)      │
│    失败 → VALIDATION_REPAIR_INSTRUCTION 回炉修复     │
└─────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 4. 端侧渲染 (C++ core)                               │
│    流式解析 → 虚拟组件树 → diff → 三端原生渲染        │
│    (iOS / Android / HarmonyOS)                       │
└─────────────────────────────────────────────────────┘
```

### 1.1 Prompt 构建（`playground/studio/server/benchmark/generation/prompt_builder.py`）

system prompt 是多段拼接的（`\n\n---\n\n` 连接）：

| 段 | 来源 | 作用 |
|---|---|---|
| 任务指令 | `MULTIMODAL_TASK_INSTRUCTIONS` | 描述任务（如"把设计图还原为 A2UI v0.9"） |
| **校验契约** | `_render_validator_contract()` 直接从 `validate_a2ui.py` 生成 | 组件/样式/icon 白名单、enum、必填字段、硬性规则 |
| Skill 规范 | `SKILL.md`（Non-Negotiables 段）+ `reference/*.md` 按模式裁剪 | 卡片约束、布局规则、数据绑定规则、视觉规范 |
| 可选段 | 占位图指令 / 数据文件指令 | 按需注入 |
| 输出格式 | `OUTPUT_INSTRUCTIONS` | 强制输出两个 JSON 代码块 |

user prompt 侧：Query + 可选的样例数据（`### 输入数据`）+ 必需绑定路径提示（`required_bindings`）+ 多模态验收约束（必须/禁止的组件类型）。

### 1.2 模式选择（`SKILL.md`）

三种模式：**DTO Component**（有 DTO 要组件 → 额外交付 Python transformer）、**Non-DTO Component**（默认，生成卡片）、**Non-DTO Page**（整页）。默认生成卡片，除非用户明确要整页。卡片场景有硬性自检（主区块 ≤3、正文 ≤2 段、高度 ≤ 2/3 屏等）。

### 1.3 输出与校验修复闭环（`playground/studio/server/generator.py`）

LLM 输出 → `extractor.py` 提取 → `validate_a2ui.py` 校验 → 失败则把错误列表 + 原始输出拼成 `VALIDATION_REPAIR_INSTRUCTION` 重新请求修复 → 再校验。通过后进入渲染。

### 1.4 端侧渲染（`core/` C++ 引擎）

`agenui_message_parser` 解析协议 → 虚拟 DOM（`virtual_dom/`）管理组件树 → `datamodel` 数据绑定 → `token_parser`/`style_parser` 解析 Design Token 与样式 → diff 后同步三端渲染层。`component_property_spec/agenui_component_spec_config.h` 定义每个组件的属性默认值/enum 与样式映射。

## 二、如何保障精准使用内置组件（四层防线）

### 防线 1：Catalog Schema 约束（对外/通用）

`agenui_catalog.json` 是符合 A2UI v0.9 的 freestanding JSON Schema（25 组件 + 14 函数 + 公共类型）。对接 Agent 时作为 `catalogId` 写入 `supportedCatalogIds`，LLM 以此为约束生成合规 JSON；`unevaluatedProperties: false` 拒绝未定义属性，`const` 锁定组件名，`enum` 锁定取值。

### 防线 2：Prompt 层白名单 + 反幻觉规则

- `SKILL.md` Non-Negotiables 中的 **Component allowlist**：只允许 25 个白名单组件名，并给出常见错误名映射（Container→Card/Column、Stack→Row/Column、Badge→Text、BarChart→Chart 等），禁止从 React/Flutter/SwiftUI 搬名字。
- `reference/component-catalog.md` 给出每个组件的完整 JSON 示例、属性、enum、样式白名单和约束（仅 px、padding 四值、border 仅 solid 等）。

### 防线 3：校验契约注入（Prompt 与校验器同源）

这是设计上最关键的一环：**`_render_validator_contract()` 直接 import `validate_a2ui.py`，把可执行白名单实时渲染进 system prompt**（`prompt_builder.py:121`）。prompt 里的组件列表、样式 key 列表、enum、必填字段 = 校验器实际执行的规则，二者不会漂移。prompt hash（`build_prompt_source_metadata`）还会记录源文件内容摘要，可追溯版本。

### 防线 4：生成后脚本强校验 + 模型审查（`validate_a2ui.py`，889 行）

| 检查类别 | 内容 |
|---|---|
| 组件白名单 | `ALLOWED_COMPONENTS`（25 个），未知组件名直接报错 |
| 样式 key 白名单 | `ALLOWED_COMMON_STYLE_KEYS` / `ALLOWED_TEXT_STYLE_KEYS`，文本样式只能用于 Text/RichText |
| enum 校验 | `COMPONENT_ENUMS`（如 Text.variant、Image.fit）+ `STYLE_ENUMS` |
| 必填字段 | `COMPONENT_REQUIRED_FIELDS` |
| icon 白名单 | `ALLOWED_ICON_NAMES`（46 个） |
| 结构规则 | root 不得设 background-color、padding/margin 必须四值、border-radius 单值、children 引用必须存在、绑定路径必须在 dataModel 中可解析等 |
| 语义检查 | 占位图 URL 黑名单、按钮文本路径检查等 |

`reference/review-validation.md` 定义脚本通过后的**模型审查轮**：组件名是否都在白名单、数据路径是否可解析、360px 溢出检查、受保护内容换行检查等；脚本与模型审查交替进行直到双双通过。

**兜底**：Studio 端还有校验失败自动修复重试（`VALIDATION_REPAIR_INSTRUCTION`）。

## 三、如果要新增组件，应该做哪些事情

新增一个内置组件（以扩展组件 Carousel/Table 为参照）需要改以下位置：

### 3.1 C++ 核心引擎（`core/`）

1. **属性规格配置**：`core/src/surface/component_property_spec/agenui_component_spec_config.h` — 添加组件的属性默认值、enum 与 variant→styles 映射（参照 `"Carousel"` 条目）。
2. **解析与虚拟 DOM**：`agenui_message_parser` / `virtual_dom` / `component_manager` 按需支持新组件节点的创建与属性下发。
3. **样式/Token**：若需新样式属性，同步 `style_parser` / `token_parser` / `style_defaults`。

### 3.2 三端渲染实现与注册

| 平台 | 实现位置 | 注册方式 |
|---|---|---|
| Android | `platforms/android/.../render/component/impl/XxxComponent.java`（继承 `A2UIComponent`）+ `factory/XxxComponentFactory.java` | 工厂类加 `@BuiltInComponent` 注解，注解处理器自动生成 `BuiltInComponentRegistrar` 完成注册 |
| iOS | `platforms/ios/AGenUI/Classes/Render/Component/Impl/XxxComponent.swift`（继承 `Component`） | 在 `ComponentRegister.swift` 的 `registerBuiltInComponents()` 中添加 `register("Xxx") { ... }` |
| HarmonyOS | `platforms/harmony/agenui/src/main/cpp/a2ui/render/components/` | 在 `render/factory/a2ui_default_registry.cpp` 中 `r->registerFactory(...)` |

公共基类/接口：Android `A2UIComponent` / `IComponentFactory`，iOS `Component` + `ComponentRegister`，鸿蒙 `A2UIComponentCreator`。自定义（非内置）组件则无需改 SDK，直接用运行时 API：`registerComponent(type, factory)` 三端均有（见 `docs/API.zh-CN.md` 自定义组件章节）。

### 3.3 生成侧（让 LLM 能"看到"并用对新组件）

4. **组件目录**：`skills/a2ui-generation/reference/component-catalog.md` — 添加组件的 JSON 示例、属性、enum、样式说明。
5. **校验器白名单**：`skills/a2ui-generation/scripts/validate_a2ui.py` — 更新 `ALLOWED_COMPONENTS`，如有新属性 enum / 必填字段 / 样式 key，同步更新 `COMPONENT_ENUMS` / `COMPONENT_REQUIRED_FIELDS` / `ALLOWED_COMMON_STYLE_KEYS` 等。
6. **Studio prompt**：无需手工改——`_render_validator_contract()` 会自动从校验器生成契约段；但要跑通 `prompt_builder` 相关测试（`test_extractor.py` 等）确认无回归。

### 3.4 Catalog 与文档

7. **`agenui_catalog.json`**：添加组件 Schema（`const` 组件名 + properties + required，参考现有组件写法，`unevaluatedProperties: false`）。
8. **README（中英文）**：组件表格新增一行（区分 A2UI 协议组件 / SDK 扩展组件），更新组件数量文案。
9. **`docs/API.zh-CN.md`** / QuickStart：如涉及 API 或用法变化则补充。

### 3.5 Playground 演示与测试

10. **Playground 演示**：三端 Playground 添加示例页面/卡片（参照 Chart/Markdown/Lottie 示例组件的做法）。
11. **测试**：`tests/cpp/` 引擎解析与 diff 用例；`platforms/android/src/test/.../ComponentRegistryTest.java` 等端侧注册测试；如改了 skill 校验器，补 `validate_a2ui.py` 对应用例。

### 3.6 最小路径（仅业务自定义，不改 SDK）

如果只是业务方想加一个组件给 LLM 用：用三端 `registerComponent` API 注册 → 在自己维护的 catalog/Skill 文档中补充组件说明即可，无需动 `core/`。
